# Skills 未知 GitHub 来源与仓库链接设计

**状态：**待用户审阅（根据“锁文件中没有条目”的场景补充）
**日期：**2026-09-27

## 目标

让 AgentPack 对已知 GitHub 来源的 Skills 提供清晰的仓库跳转和更新检查；对仍无法确认来源的 Skill 明确报告“未检查”，不再让用户误以为它已是最新。

## 当前行为

- `Store.CheckUpdates` 只收集 `RepoOwner` 和 `RepoName` 都非空的 Skill。无来源条目从结果中消失。
- 当所有已安装 Skill 都没有 GitHub 来源时，检查结果为空，前端可能显示“全部最新”。
- `ParseAgentsLock` 仅在 `sourceType == "github"` 且 `source` 可解析时恢复仓库所有者与仓库名；有效 GitHub `sourceUrl` 本身不能回填这些字段。
- 应用启动时已有基于 skills.sh 候选及本地/远端内容校验的自动来源回填。它只接受可验证匹配项。
- 启动后新安装或导入的 Skill 不会自动经过这次启动回填；当前更新检查也不会先尝试回填。
- 已安装 Skill 卡片当前不显示仓库链接。

## 设计

### 1. 从锁文件恢复可信 GitHub 来源

保留现有 `sourceType=github` 和 `source=owner/repo` 的解析优先级。若这组字段不完整，则可从 `sourceUrl` 恢复来源，但仅接受 HTTPS、主机名严格等于 `github.com`、路径至少包含合法 `owner/repo` 的 URL。不得接受子域冒充、userinfo、非 HTTPS、无效坐标或任意第三方主机。

分支和技能目录路径继续优先使用锁文件中已有的 `branch`、`sourceBranch` 和 `fullPath`。若 `sourceUrl` 是仓库根 URL 且锁文件没有分支，沿用更新检查的默认分支规则。来源恢复结果只写入内存状态；不得因读取锁文件而重写或迁移用户锁文件。

自动来源回填仍保留：候选来源必须通过当前内容验证后才可记录。点击“检查更新”时，在更新检查前自动尝试回填当前仍无可信来源的 Skills，包括锁文件中没有条目的 Skill。启动时已有的自动回填也保留。不得根据 Skill 名称、描述或文件内容猜测一个未经验证的 GitHub 仓库。

回填应在更新检查取得其存储操作锁之前完成，避免回填写入锁文件/更新内存状态时与同一把锁互相等待。回填完成后使用最新 Skill 状态执行更新检查。若回填服务不可用或没有可验证匹配项，继续检查其他已知来源 Skills，并将未匹配项报告为来源未知/未检查；回填失败不能被解释成“无更新”。同一轮更新检查中不得对同一 Skill 重复回填。

### 2. 将未知来源表示为未检查

更新检查结果必须覆盖所有受 AgentPack 管理的 Skills：

- 有可信 GitHub 来源的 Skill 按现有内容级更新检测流程检查。
- 没有可信来源的 Skill 返回显式 `sourceMissing` 状态；不将其标记为“无更新”，也不对它执行更新。
- 检查更新前自动尝试对无来源 Skills 执行一次已有的、内容验证式来源回填；回填后重新读取 Skill 状态再检查。
- 网络或远端错误仍使用现有错误状态，与“来源未知”分开。

前端卡片显示来源未知/未检查状态。检查完成提示应分别计算发现更新、检查失败、来源未知和成功检查且无更新的数量；只有全部受检 Skills 均成功且不存在来源未知项时，才可显示“全部最新”。

### 3. GitHub 仓库跳转

当 Skill 拥有可信 `repoOwner` 和 `repoName` 时，卡片提供 GitHub 仓库链接，目标为 `https://github.com/{owner}/{repo}`。链接使用外部浏览器打开。来源未知的 Skill 不显示 GitHub 链接。

此链接用于查看仓库，不提供绑定、编辑或改变更新来源的操作。

## 范围外

- 不添加手动绑定 GitHub 来源的按钮或编辑弹窗。
- 不为完全没有来源证据的 Skill 推断上游仓库。
- 不改变已知来源 Skills 的文件树 API、内容哈希、更新与回退算法。
- 不改变 skills.sh 自动回填的候选来源或内容验证规则。

## 验收标准

1. 完整 GitHub 来源字段仍按现有行为解析。
2. `source` 缺失但存在可信 GitHub `sourceUrl` 时，恢复仓库坐标，并使用已有分支/路径元数据。
3. 带非 GitHub 主机、伪造主机后缀、userinfo 或非 HTTPS 的 URL 不产生来源，也不产生 GitHub 链接。
4. 没有来源的 Skill 出现在更新检查结果中，状态为来源未知/未检查，且永不伪装成无更新或进入更新队列。
5. 只有检查成功且所有 Skill 均已检查时，前端才显示“全部最新”。
6. 有来源的卡片链接精确指向其 GitHub 仓库；无来源卡片没有链接。
7. 用户锁文件内容不因来源解析而被改写。
8. 锁文件中不存在记录的 Skill 会在启动回填或下一次手动检查更新前进入自动回填；只有本地内容与候选上游完全验证匹配后才补入来源，否则显式显示来源未知/未检查。
9. 更新前回填与更新检查顺序不会造成存储锁重入或死锁；回填服务失败时仍能返回已知来源 Skills 的检查结果。

## 验证重点

- 锁文件中的 URL 解析边界、路径和分支优先级。
- 无来源、部分有来源、全部有来源、网络失败混合状态下的更新结果和提示。
- 外部 GitHub 链接的目标域和路径构造。
- 现有自动回填与已有更新检测回归。
